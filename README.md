# sledgehammer

The frozen Repose V9.3 cube-reorientation planner for [ViBe](https://github.com/lok-i/vibe).
An optional demo alongside tracker deployment in [vibe_ws](https://github.com/drcl-deploy/vibe_ws).

## usage

Build through [vibe_ws](https://github.com/drcl-deploy/vibe_ws#install).
Start the simulator executable and cpp_control tracker in their own terminals;
the workspace [usage commands](https://github.com/drcl-deploy/vibe_ws#usage)
show their exact model paths and V9.3 parameters.

In terminal 3, from the workspace root:

```bash
source setup_local.sh
ros2 launch sledgehammer planner.launch.py env:=sim
```

The planner and interactive console share this terminal, including over SSH/tmux.
**0–5** or **r/o/g/y/b/p** selects red/orange/green/yellow/blue/pink live for both
planner and tracker. **R** resets the current target's trial. The initial target
is blue (`goal_color:=4`); use the same initial value in the tracker launch.

**RB** enters nominal stand and disarms; **A** arms from stand once the planner
is available. **q** or **Ctrl-C** closes the console and stops the planner.
Planner logs go to the ROS launch log directory while the console is visible.

Onboard: source `setup.sh onboard`, then use `env:=real`; targets are still entered
in the same SSH/tmux pane. Without a TTY, the launch starts only the planner.
Set `console:=false` to explicitly disable the console. A separate console remains
available as `ros2 run sledgehammer repose_console.py`.

The C++ tracker exits if this planner stops publishing its heartbeat for one second;
its ROS launch then stops the encoder and bridge. The planner idles when
controller status or low-state becomes stale. Restart the tracker launch after
restarting the planner.

Both planner camera consumers reconnect after a two-second connection/frame
timeout, including an incomplete frame. Ctrl-C interrupts socket and retry
waits even when the camera keeps its connection open without sending.

## data

| file | purpose |
|---|---|
| `data/sys1_clips.npz` | clip table |
| `data/sys1_library.npz` | frozen source library |
| `data/sys1_bundle.npz` | selected motion frames, including contact commands |
| `data/sys1_walk/.../motion.npz` | approach and disarmed walking |

All four files ship in this repository and install with the planner runtime.
[data.lock.json](data.lock.json) records hashes and provenance. V9.3 reads the
baked frames without a training checkout. See [data notes](data/README.md) for
the verified array equality and the sidecars required when rebaking.

Policy and encoder ONNX belong in the workspace's ignored `artifacts/`.
Tracker inference, robot control, `MotionReference` and `ControllerStatus` remain in
[cpp_control](https://github.com/drcl-deploy/cpp_control). Repose-specific
`PlannerStatus`, `CubeObservation` and `CalibrationState` are generated by this
package. The controller consumes `std_msgs/msg/Empty` on
`/vibe/planner/heartbeat`, emitted from the same planner tick as status. Topics stay
`/tracker/reference`, `/vibe/controller/status`, `/vibe/planner/status`, `/lowstate`
and `/vibe/sonic/goal_color`.

`-DSLEDGEHAMMER_BUILD_RUNTIME=OFF` installs messages and viewing tools without
building planner executables or installing frozen data. The workspace uses this
for offboard installs, so telemetry does not require an ONNX/CUDA SDK.
Replay/validation tools accept the former `cpp_control/msg/...` type names in
saved bags; fields and serialized layout are unchanged. This is reader
compatibility, not a live ROS type alias.

## test

```bash
colcon test --packages-select sledgehammer
colcon test-result --verbose
```

Nine package tests cover historical presets, V9.3 planning with shipped data,
and voice-key parsing. The workspace adds isolated disconnect checks and the
operator regression. Joystick and hardware acceptance remain pending.
